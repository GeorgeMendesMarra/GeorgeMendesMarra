# Processos de Software — Engenharia de Software

## Ementa

O processo de software e o produto de software. Ciclo de vida de sistemas e seus paradigmas. Processos, metodologias, técnicas e ferramentas de análise e projeto de sistemas de software segundo um paradigma de desenvolvimento atual.

## O que o aluno precisa fazer

Com base nessa ementa, a disciplina de Processos de Software foca em entender **como** o software é construído (processo) e não apenas o resultado final (produto). De forma geral, o aluno precisa:

### 1. Dominar os conceitos fundamentais

- Diferenciar processo de software x produto de software
- Entender os principais modelos de ciclo de vida (cascata, incremental, iterativo, espiral, ágil) e quando cada um se aplica
- Conhecer as fases clássicas: levantamento de requisitos, análise, projeto, implementação, testes, implantação e manutenção

### 2. Trabalhar com metodologias e paradigmas atuais

- Comparar abordagens tradicionais (plan-driven, como RUP) com abordagens ágeis (Scrum, XP, Kanban)
- Aplicar um paradigma de desenvolvimento atual em um estudo de caso ou projeto prático — normalmente é aqui que entra a parte mais "mão na massa" da disciplina

### 3. Usar técnicas e ferramentas de análise e projeto

- Modelagem de sistemas (UML costuma aparecer aqui: casos de uso, diagramas de classe, atividades, sequência)
- Especificação técnica de software (ligando com o livro do Lima)
- Possivelmente estimativas de esforço/tamanho, como Análise de Pontos de Função (dado que está na bibliografia complementar)

### 4. Discutir qualidade e gestão

- Qualidade e produtividade em processos de software (normas, boas práticas)
- Papel da TI na organização (ligando com Turban/Rainer/Potter)

### Entregas típicas em disciplinas com essa ementa

- Trabalho prático de modelagem de um processo de software para um sistema fictício ou real
- Comparativo entre metodologias (ex: cascata vs. Scrum) aplicado a um estudo de caso
- Documento de especificação técnica de um software
- Seminário/apresentação sobre um dos temas da bibliografia complementar (ágil, pontos de função, qualidade)
