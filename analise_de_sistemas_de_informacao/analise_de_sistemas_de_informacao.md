A disciplina de Análise de Sistemas de Informação ocupa um lugar central na formação em Engenharia de Software: é a ponte entre o "mundo do problema" (necessidades do negócio, do usuário) e o "mundo da solução" (o software propriamente dito). Suas principais funções no currículo são:

**1. Desenvolver a capacidade de levantamento e análise de requisitos**
Ensina o aluno a entender e formalizar o que um sistema precisa fazer antes de programar — entrevistas, questionários, análise de processos de negócio, casos de uso.

**2. Introduzir o raciocínio orientado a objetos**
Antes de codificar, o aluno aprende a modelar o domínio do problema em termos de classes, objetos, relacionamentos e comportamentos — uma habilidade que sustenta praticamente todo o desenvolvimento moderno (Java, C#, Python etc.).

**3. Ensinar a documentar e comunicar soluções de forma padronizada**
Com UML (casos de uso, classes, objetos, sequência), o aluno aprende uma linguagem visual comum, usada por equipes de desenvolvimento no mercado inteiro — essencial para trabalho em times e para dar manutenibilidade ao software.

**4. Preparar para metodologias e processos formais**
Ao estudar o Processo Unificado, o aluno entende como a análise se encaixa dentro de um ciclo de vida iterativo e incremental — base conceitual que depois se conecta com metodologias ágeis (Scrum, Kanban).

**5. Desenvolver pensamento crítico sobre qualidade de projeto**
Discutir análise x projeto ajuda o aluno a perceber decisões de design que impactam manutenibilidade, extensibilidade e reuso — prevenindo problemas que só apareceriam tarde no ciclo de desenvolvimento.

Em resumo, é a disciplina que ensina a "pensar antes de programar" e a comunicar esse pensamento de forma estruturada — habilidade que separa quem só programa de quem projeta sistemas.

**Programas/ferramentas que poderiam ser usados na disciplina:**

| Categoria | Ferramentas |
|---|---|
| Modelagem UML (gratuitas/didáticas) | **StarUML**, **Astah Community**, **draw.io / diagrams.net**, **Umbrello** (Linux) |
| Modelagem UML profissional | **Enterprise Architect**, **Visual Paradigm**, **Lucidchart** |
| Ferramentas CASE integradas | **Visual Paradigm** (também gera código a partir de diagramas), **Enterprise Architect** |
| Prototipação de requisitos/casos de uso | **Figma** (protótipos de tela), **Balsamiq** (wireframes) |
| Versionamento e documentação colaborativa | **GitHub/GitLab** (para versionar diagramas em texto), **Notion/Confluence** (documentação de requisitos) |
| Diagramas como código (texto → UML) | **PlantUML**, **Mermaid** |

Para uma disciplina didática, uma combinação leve costuma funcionar bem: **draw.io** ou **StarUML** para os diagramas (gratuitos, curva de aprendizado baixa) e **PlantUML/Mermaid** para ensinar a gerar diagramas a partir de texto.
